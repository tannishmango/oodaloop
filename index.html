OODALOOP

An escalation and recovery harness for agentic coding under consequential uncertainty. Most software work should not use it.

Act from the best current map, notice when the territory contradicts it, and re-orient before a bad trajectory compounds.

Stay out by default

Can this be safely executed and verified without unresolved consequential judgment? │ ├─ yes → ordinary execution │ └─ no │ ├─ can lightweight local planning resolve it? │ └─ yes → ordinary plan → execute │ └─ no → OODALOOP

A plan, multiple files, or moderate complexity are not enough reason to enter the framework. A mechanical 20-file change may stay ordinary; a small authorization or migration change may deserve deep orientation.

What OODALOOP adds

Observe
Gather evidence that can actually change the approach. Use a blind-spot pass when novelty warrants it.
Orient
Identify the consequential judgment an executor would otherwise have to invent.
Decide
Resolve those choices and decompose only until work becomes executable leaves.
Act
Execute leaves cheaply, prove them proportionately, and interrupt on material surprise.
Reconcile
Close clean work quickly; REFINE or RESCOPE only when evidence actually changed the map.

Weakest sufficient commitment

Minimize residual consequential decisions while preserving maximum implementation optionality.

Plans should be strong about required behavior, invariants, constraints, dependencies, acceptance, proof, and safety boundaries. They should remain weak about incidental implementation choices that the evidence does not constrain.

Leaf readiness

A node is an executable leaf when a competent executor can finish it without inventing product intent, choosing architecture, discovering substantial new scope, or making another high-impact trade-off absent from the spec.

Surprise is the runtime interrupt

surprise ├─ contained / mechanical → quick local fix ├─ under-decomposed → Decide ├─ map / evidence wrong → Observe / Orient └─ high-risk / preference → user judgment

Unknown unknowns cannot be exhaustively planned away. The harness instead makes their observable consequence—contradicted assumptions, unexpected coupling, consequential new choices, unexplained proof failure, or material scope expansion—hard to glide past silently.

Review must earn its cost

Routine leaves close on proportionate evidence. There is no mandatory tri-mode assessor and no second-model approval tax after every leaf. A fresh-context reviewer is optional for architecture, security/safety, material surprise, integration uncertainty, or ambiguous proof.

Host substrate, not core ceremony

subagentsworktreesparallelismpermissionshooksmodel routing

Hosts may provide these capabilities. OODALOOP consumes them through adapters without making them semantic state. Hooks are for deterministic must-happen facts and safety boundaries—not architecture judgment.

State for recovery, not paperwork

.oodaloop/ CONTEXT.md curated reusable knowledge BACKLOG.md real future work <slug>.task.md ephemeral active node CYCLES.log optional cheap telemetry

Persist surprising, reusable knowledge that materially improves future trajectories. Do not turn context into a transcript.

Design test

OODALOOP succeeds when genuinely uncertain work gets better orientation and ordinary software work usually never enters the framework at all.
